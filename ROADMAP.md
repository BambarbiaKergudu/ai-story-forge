# AI Story Forge — Роадмап

Оценки в часах чистой работы. Базовое допущение — 10–12 часов в неделю (вечера +
часть выходного), значит **~8 недель до состояния «можно показывать»**.

Оценки учитывают, что фронтенд для тебя рутина, а NestJS, Prisma, BullMQ и деплой —
зона роста, поэтому backend-задачи заложены с запасом ×1.5.

Порядок фаз выбран по принципу «раньше делаем то, что может убить проект»: сквозной
рабочий срез на первой неделе, риск консистентности персонажа — на второй, красивый
UI — только после того, как ядро работает.

## Фаза 0. Фундамент — 10 ч

| Задача                                                                                        | ч   |
| --------------------------------------------------------------------------------------------- | --- |
| pnpm workspaces, `apps/web`, `apps/api`, `packages/contracts`, общий tsconfig/eslint/prettier | 2   |
| `docker compose`: Postgres + Redis, `.env.example`                                            | 1.5 |
| Prisma: схема из ARCHITECTURE §3, первая миграция, сид                                        | 2.5 |
| Каркас NestJS: конфиг через `@nestjs/config` с валидацией env, pino-логгер, `/health`         | 2   |

**Готово, когда:** `docker compose up` + `pnpm dev` поднимает оба приложения, `web`
успешно дёргает `/health` у `api`, CI зелёный.

## Фаза 1. Вертикальный срез без картинок — 14 ч

Цель — сквозной путь «идея → текстовая история в БД → на экране». Пока синхронно,
без очереди: сначала работающий скелет, потом асинхронность.

| Задача                                                                      | ч   |
| --------------------------------------------------------------------------- | --- |
| zod-схемы сценария в `packages/contracts`                                   | 1.5 |
| Модуль `llm`: клиент Groq, промпт-шаблон, structured output                 | 3   |
| Валидация ответа + ретрай с ошибкой в промпте                               | 2   |
| Модуль `stories`: `POST /v1/stories`, `GET /v1/stories/:id`, запись панелей | 3   |
| Сервисный JWT: подпись в `web`, guard в `api`                               | 2   |
| Простейший UI: форма идеи + список панелей текстом                          | 2.5 |

**Готово, когда:** ввёл идею — через несколько секунд видишь 4 сцены с текстом и
промптами, всё лежит в Postgres.

**Ловушка:** не увлекайся промпт-инжинирингом. Достаточно «приемлемо», вернёшься в
фазе 6.

## Фаза 2. Картинки, очередь, SSE — 18 ч

Самая тяжёлая и самая ценная фаза: здесь появляется всё, ради чего проект затевался.

| Задача                                                                             | ч   |
| ---------------------------------------------------------------------------------- | --- |
| **Спайк консистентности персонажа** (см. ниже)                                     | 3   |
| Модуль `images`: единый интерфейс, адаптер fal.ai                                  | 2.5 |
| Модуль `storage`: скачивание, WebP через `sharp`, загрузка в R2                    | 2.5 |
| BullMQ: очереди `script` и `panel-image`, воркеры, конкурентность, идемпотентность | 4   |
| Перевод `POST /v1/stories` на `202` + машина состояний истории                     | 2   |
| SSE-эндпоинт, heartbeat, проксирование через `web`                                 | 2.5 |
| Клиентский хук `useStoryStream` + восстановление состояния при разрыве             | 1.5 |

**Спайк по консистентности** — отдельный скрипт, не часть приложения. Прогони одну
историю тремя способами: (а) голый промпт, (б) промпт + «паспорт персонажа» + общий
seed, (в) Gemini с первой панелью как референсом. Сложи 12 картинок рядом и выбери.
Это решение определяет и качество демо, и цену — узнать его надо до того, как вокруг
него построен UI.

**Готово, когда:** нажал кнопку — текст появился через 3 секунды, панели
дорисовываются по одной, обновление страницы во время генерации ничего не ломает.

## Фаза 4. UI, ради которого всё показывают — 14 ч

Твоя сильная зона, но именно её увидит рекрутёр в первые 20 секунд.

| Задача                                                                      | ч   |
| --------------------------------------------------------------------------- | --- |
| Просмотрщик историй: полноэкранные слайды, свайпы, клавиатура, прогресс-бар | 5   |
| Framer Motion: появление панелей, скелетоны, переходы между сценами         | 3   |
| Инлайн-редактирование текста панели (оптимистично)                          | 2   |
| Перегенерация картинки, в том числе с правкой промпта                       | 2   |
| Дашборд со списком проектов, пустые состояния, тосты ошибок                 | 2   |

**Готово, когда:** историю приятно листать на телефоне, и ни одно состояние
(загрузка, ошибка, пусто) не выглядит как необработанное.

## Фаза 5. Надёжность — 14 ч

Фаза, которая и превращает «сайт с кнопкой» в инженерный проект. Именно про неё ты
будешь говорить на интервью.

| Задача                                                                      | ч   |
| --------------------------------------------------------------------------- | --- |
| Классификация ошибок retryable/fatal, backoff, таймауты с `AbortController` | 3   |
| Fallback между image-провайдерами, адаптер Gemini                           | 2.5 |
| Cron добивания зависших историй, статус `PARTIAL` в UI                      | 1.5 |
| Unit-тесты: валидация ответа LLM (включая битые JSON), расчёт квот          | 3   |
| Интеграционный тест пайплайна на Testcontainers с замоканными провайдерами  | 3   |
| Sentry на обоих приложениях, `/admin/jobs`                                  | 1   |

**Готово, когда:** можно выдернуть Redis или заставить провайдера отдавать 500 — и
приложение деградирует предсказуемо, а не падает.

## Если время поджимает

Урезать надо не качество ядра, а объём. В порядке отказа:

1. Режим `consistent` на Gemini — оставить только FLUX schnell и «паспорт персонажа».
2. Гостевой режим — сразу требовать регистрацию, но завести демо-аккаунт в README.
3. Админка `/admin/jobs`.
4. Шаринг-ссылки и OG-картинки.

**Нельзя выкидывать ни при каких обстоятельствах**, потому что именно это и есть
предмет разговора на собеседовании: очередь с ретраями, SSE с частичными
результатами, валидация ответа LLM, квоты и учёт стоимости, тесты пайплайна, деплой
на VPS в Docker.
